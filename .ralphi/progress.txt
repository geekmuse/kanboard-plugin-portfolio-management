## Codebase Patterns
- Task form hooks use `template:task:form:first-column` to inject fields into Kanboard's task creation form; `params['project_id']` carries the project context (also check `params['task']['project_id']` defensively).
- `task.create` event receives all form values including custom fields added by hook templates; listener can read `$event['milestone_id']` to process post-creation side effects.
- Widget templates that receive pre-fetched data via `attachCallable` follow the pattern: check `! empty($varName)` at top → render content → close endif; this keeps templates minimal and testable.
- New FakeMilestoneTaskModel in ApiRegistrationTest: `$addCalls[]` records `[$milestoneId, $taskId]` tuples; set in container after `initialize()` for listener behavioral tests.
- Event listener tests: use FakeDispatcher.listeners[eventName][0](array) to invoke registered callbacks with an ArrayAccess-compatible plain array (no Kanboard runtime needed).
- DependencyModel event chain: `onTaskClosed` calls `dispatchDependencyResolvedEvent` which routes through the container's 'dispatcher' service (if it has a `dispatch()` method) — use DependencyTestEventDispatcher or FakeDispatcher in tests.
- Deep behavioral tests for Plugin event wiring live in `Test/Plugin/ApiRegistrationTest.php`; per-method DependencyModel behaviour tests live in `Test/Model/DependencyModelTest.php`.
- When an acceptance criterion is already satisfied by an existing test, verify the mapping explicitly, run all quality gates, and mark the story done without adding redundant tests.

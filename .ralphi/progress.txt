## Codebase Patterns
- `getWorkload()` uses the same accumulator-style pattern as `buildTaskDependencyStats()`: initialize per-owner_id sub-arrays once, then mutate with `++$accumulators[$ownerId]['field']`. PHPStan level 5 allows `++` on inferred-int fields in such arrays without explicit `@var` annotation.
- For per-user project breakdowns in workload accumulators: extract `$ownerProjects = (array) $accumulators[$ownerId]['projects']`, modify it, then reassign back. PHPStan flags `is_array(...) ? ... : []` as always-true when the value was initialized as `[]` — use `(array) $value` cast instead.
- API registration test name after US-006: `testRegistersAllThirtyOneJsonRpcMethods` (31 methods). Update name + expected array when adding new JSON-RPC methods.
- `time_spent INTEGER NOT NULL DEFAULT 0` must be in the test tasks table DDL for workload tests that check `total_spent_hours`. `insertTask()` omits it (defaults to 0 from schema).
- Workload unassigned bucket: after extracting from `$accumulators[0]`, unset `user_id`, `username`, `name` keys before returning — the API contract for unassigned omits user identity fields.
- `buildEmptyWorkloadResult()` helper returns the canonical empty workload structure — reuse it in all early-return paths of `getWorkload()`.


- For `git commit` to succeed when the pre-commit hook runs `ralphi check` + phpstan Docker (which takes ~46s), call `git commit` with `timeout: 300` in the Bash tool. Using the default 30s timeout causes the tool to report "Command timed out" even though the commit may be in progress.

- `docker-phpstan.sh` requires `--memory-limit=512M` flag; the default 128M container limit causes a crash/timeout. Fixed in scripts/docker-phpstan.sh — always use the updated script.
- `project_activities` table schema for tests: `id INTEGER PRIMARY KEY AUTOINCREMENT, project_id, task_id, event_name TEXT, creator_id INTEGER, date_creation INTEGER, data TEXT`. The defensive try/catch in `getActivity()` handles both missing-table and wrong-table-name cases.
- `getActivity()` follows the same in-memory scan pattern as `buildFilteredTaskRows()`: fetch all rows from the table, filter by projectScope map, then sort/paginate. This is consistent cross-driver behavior without raw SQL JOINs or IN clauses.
- API registration test name tracks method count: after US-004 it is `testRegistersAllThirtyJsonRpcMethods` (30 methods). Update name + expected array when adding new JSON-RPC methods.
- GET forms in templates use `$this->url->href(...)` as action; in real Kanboard path-based routing preserves controller/action/plugin in the URL path, so form fields only need to carry non-routing params. Follow the same pattern as `Template/portfolio/tasks.php` filter form.
- For MilestoneControllerFakeMilestoneModel: when extending `getProgress()` to accept `$weightBy`, add a separate `getProgressWeightByCalls: array<int, string>` so existing tests that assert `getProgressCalls` (milestone IDs) still pass.
- `MilestoneController::getMilestoneProgress()` fallback array should mirror all keys returned by `MilestoneModel::getProgress()` (incl. `no_data`, `weight_by`, `score_*`, `time_*`) so `array_merge($fallback, $progress)` always produces a complete result regardless of what the model returns.
- All model methods that delegate to dependencyModel use `resolveContainerService('dependencyModel')` + `is_object() && method_exists()` guard + `try/catch Throwable`. PHPStan level 5 is satisfied because `is_object()` narrows `mixed` to `object`.
- The test harness for PortfolioTaskModel: create stub classes in the same file (PSR1.Classes.ClassDeclaration is relaxed for Test/), use in-memory SQLite with manual DDL in setUp(). Pass overrides via `createModel(['serviceKey' => $stub])`.
- `insertTask()` in PortfolioTaskModelTest has an optional `$dateCompleted = 0` final parameter. All existing callers omit it safely (defaults to 0 via column DEFAULT 0).
- Pre-existing PHPCS error in PortfolioViewControllerTest.php line 933 (inline anonymous class brace formatting) — fix on sight when editing that file.
- API registration test is named `testRegistersAllTwentyNineJsonRpcMethods` (updated from 28). Update name + expected array when adding new JSON-RPC methods.
- MilestoneModelTest tasks table needs `score INTEGER NOT NULL DEFAULT 0` and `time_estimated INTEGER NOT NULL DEFAULT 0` for weighted progress tests. PortfolioTaskModelTest tasks table needs `time_estimated INTEGER NOT NULL DEFAULT 0` for calculateMilestoneHealth to return time fields.
- When extending MilestoneModel::getProgress() return array with new fields, all existing tests still pass because they check specific keys — new keys in the return array don't break assertions.
- ConfigController getDefaultSettings/normalizeSubmittedSettings/getCurrentSettings follow a consistent pattern: add key to getDefaultSettings (int or string), getCurrentSettings handles generically, normalizeSubmittedSettings needs explicit normalization per key type.
- Multi-line function declarations in PSR-12: `)` closing paren must be on the same line as `): ReturnType {` (i.e., `): void {` not `): void\n    {`).

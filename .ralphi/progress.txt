## Codebase Patterns
- Preserve planned empty plugin folders in git with `.gitkeep` files so the Kanboard plugin scaffold stays visible and reviewable before concrete implementations land.
- Migration driver files (`Schema/Sqlite.php`, `Schema/Mysql.php`, `Schema/Postgres.php`) intentionally share the same namespace-level `VERSION` constant and `version_1()` symbol, so cross-driver verification should statically inspect non-active driver files instead of requiring all three in one PHP process.
- For early DI wiring stories, create minimal namespaced placeholder classes (extending `Kanboard\Core\Base`) so container factories can resolve immediately and be validated before full model/helper logic lands.
- For model-unit stories before Kanboard runtime is available, use an in-memory SQLite test harness with a tiny PicoDb-like adapter (`table()->eq()->asc()->find*()/insert/update/remove`) plus a minimal `Kanboard\Core\Base` stub to validate model behavior and schema cascades.
- For membership-style model reads, querying the junction table first and then enriching rows with entity lookups avoids coupling early tests to JOIN support while keeping output ordering deterministic.
- Model update methods should treat `null` values as "field omitted" when API callbacks pass `compact(...)` defaults, preventing accidental validation failures on untouched fields.
- Dependency link processing should normalize edge direction from `links.label`/`links.opposite_label`, so dependency queries work even when stored rows use either `blocks` or `is blocked by` as the primary label.
- Critical-path evaluation should use unresolved active dependency edges only and deterministically break cycles by dropping the newest edge before DAG longest-path calculation.
- Unified portfolio task listing stays deterministic in the lightweight PicoDb harness when dependency, milestone, and lookup maps are precomputed once and filters/sort/pagination are applied in memory.
- Plugin-level API registration can be tested without a full Kanboard runtime by stubbing `Base`, `api` procedure handlers, and `apiAccessMap`, then invoking captured JSON-RPC callbacks directly for delegation assertions.
- Controller integration stories can run in a lightweight harness by stubbing `request`, `response`, `template`, `flash`, and CSRF checks, while still rendering real template files to verify escaped output, CSRF fields, and redirect targets.
- Portfolio membership settings UIs stay deterministic when controllers derive `available_projects` by subtracting `portfolioProjectModel->getProjects()` IDs from `projectModel->getAll()` before rendering add forms.
- Filterable portfolio list views remain predictable when controllers normalize query params once, pass scalar `filters` values to templates, and build pagination links from a dedicated `pagination_query` map.
- Aggregate portfolio board/timeline pages remain deterministic in the lightweight harness when controllers request active tasks with fixed filter defaults, then derive grouped columns/timeline arrays before rendering templates.
- Milestone membership UI flows should post `task_id`, `is_critical`, and `position` directly to controller actions, while relying on `milestoneTaskModel->add()` for the portfolio-project validation rule to keep behavior consistent across UI/API callers.
